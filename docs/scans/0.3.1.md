## Findings
### T-01 low: troubleshooting.md `rm -r $XDG_RUNTIME_DIR/stance` is unquoted and unguarded
- docs/troubleshooting.md, `stance_runtime` fail. If the variable is unset (TTY/SSH/root shell) this becomes `rm -r /stance`;
  as root in a stray cwd that is still a wrong delete. Fix: `rm -r -- "${XDG_RUNTIME_DIR:?}/stance"`.
### T-02 low: "remove stale directories of dead instances" is vague (socket1/socket2 entry)
- A user may delete the live instance directory under `$XDG_RUNTIME_DIR/hypr/` and break their running session's IPC. Fix: say
  "only the ones whose Hyprland is no longer running (compare with `hyprctl instances`)".
### T-03 low: ufw advice is broader than needed
- `sudo ufw allow from 192.168.0.0/16 to any port 47800 proto tcp` opens the deck port to 65k LAN addresses (guest/IoT segments).
  The text says "use your LAN range"; make the example the narrow form (`192.168.1.0/24`) or the phone's single IP, and note the
  deck is PSK/Noise protected but still should not face untrusted networks.
### T-04 info: i2c advice
- "add yourself to the i2c group" gives raw I2C bus access (wrong writes can damage some monitors); add a one-line caution
  or prefer the udev rule shipped by ddcutil.
### T-05 info: CI / scripts
- `scripts/i18n-check.py` docstring promises "every Turkish entry is still used" but unused entries (45) do not fail; either fix the
  docstring or fail on them. CI `qmlformat` step fails closed (empty `$fmt` -> command not found) but with a confusing message. Actions
  are tagged (`@v4`), not SHA-pinned.
### T-06 info: StanceNav hover label
- `nav.hoverCell` keeps a reference to a delegate; if the model changes while hovering (categories hidden by a feature toggle) it
  dereferences a destroyed item (QML warning only). Label text is a static i18n string (no user data), rendered PlainText-safe.
