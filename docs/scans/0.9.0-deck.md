## Findings

### D1 medium: handshake has per-read timeouts, no total deadline (slowloris)

`accept()` sets `set_read_timeout(5 s)` once; `read_exact` in `read_frame` restarts that timeout on every byte it receives. A client that sends the mode byte, a 2-byte length of 1024 and then one byte every 4 s holds the connection for about 68 minutes per frame, three frames in PAIR mode. `MAX_HANDSHAKES = 4` slots are taken by four such sockets, after which every new connection (including paired phones) is shut down silently at net.rs:~323. The failure is only recorded in `RateLimit` when the handshake ends, so the rate limiter never sees the trickle; the "10 per IP / 40 overall" limits do nothing against it. A single LAN host (or any local process on loopback mode) is enough. Even without trickling, 4 idle connections opened every 5 s block ~100 % of the time for one IP before the per-IP failure cap (10/min) applies, about 20 % afterwards.
Reproducer: `python3 -c` open 4 TCP sockets to the deck port, send `\x01\x04\x00`, then `sleep(4); send(b'x')` in a loop; a paired phone connecting meanwhile is closed immediately.
Fix: one `Instant` deadline per handshake; before each read set the timeout to `deadline - now` (also for `hs_write`); count a slot against the IP from accept time (record a failure when the deadline hits, which the code already does on error) and cap concurrent handshakes per IP (for example 2). The post-auth `recv_plain` frame read (noise.rs:171-193) has the same per-read shape; there the peer is authenticated, but give it a frame deadline too.

### D2 medium: IK message 1 is replayable; the server then parks an unauthenticated session

Noise IK message 1 carries no responder-chosen freshness, so a captured message 1 (mode byte + one 1 KiB-max frame, observable by anyone who can sniff or ARP-spoof on the LAN once) is accepted forever: `accept()` finds the static key paired, sends message 2 and returns `Incoming::Device`. The attacker cannot derive the transport keys (no ephemeral private key), so nothing the attacker sends decrypts, but `connection()` has already counted a session, pushed the device into `connected`, written `deck-seen.json` (two fsynced atomic writes per connection) and entered `session_loop`. The loop has no idle timeout and no requirement that the client proves anything: `recv_plain` returns `Ok(None)` forever on a silent socket; the server only writes when state changes (a dead peer is eventually noticed, a live silent one never). Eight replays fill `MAX_SESSIONS`, after which real phones get "too many phones connected"; the successful handshakes are not counted by the rate limiter. The legitimate phone also shows as "connected" in `status`.
Reproducer: record the first 2 + 1 + ~100 bytes a phone sends (mode byte and frame); replay them from a second host 8 times and keep the sockets open; the 9th real connection is refused.
Fix: after `hello`, require one successfully decrypted frame (the v2 `caps`, or a `ping`) within about 10 s, then require any frame at least every 60-90 s (the app already pings) else `Bye`; count successful-but-never-authenticated sessions per IP; optionally cap sessions per device name (2).

### D3 low-medium: `notify_paired` passes the phone-chosen name as the notify-send body without `--`

`net.rs:590-607` runs `notify-send -a stance "stance: phone paired" "<name> (key ...)"`. `name` is only cleaned of control characters and length (`clean_name`), a leading `-` is allowed. libnotify parses options interleaved with positionals, so a name such as `--x` or `-h` makes the body an option and `notify-send` exits with "unknown option" (reproduced here with `DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent notify-send -a stance summary "--bogus (key AAAA-BBBB)"` -> `Bilinmeyen seçenek --bogus ...`, i.e. parse error before any notification; the same text with `--` before the positionals is accepted). Someone who photographed the QR during the window can pair under such a name and the "Not you?" notification, which is the documented mitigation for a stolen QR, never appears. (`transfer::notify` and `transfer::ask` already use `--`.) Also `name` is interpolated unfiltered into the body (`plain()` is not applied) so markup tags are interpreted by some notification daemons.
Fix: insert `--` before the summary like `transfer::notify`, and pass body through `transfer::plain`. Better: `notify_paired` should call `transfer::notify`.

### D4 low-medium: anyone on the LAN can burn the pairing window

`MODE_PAIR` calls `take_psk()` before reading a single handshake byte; it burns the PSK even for an unauthenticated stranger. During the 120 s window, one connection with the byte `0x02` (cost: nothing) disables pairing; the user sees the QR and the app failing with "pairing code was used or expired". Repeating it on every `pair` attempt makes pairing impossible for anyone who can reach the port. There is no confidentiality gain: the PSK is 256-bit, a wrong guess cannot teach anything. (Failures are rate-limited per IP but a few attempts are enough.)
Fix: take the PSK by reference for the handshake, consume it only on a successful third message (burn on success; optionally allow up to 3 failed attempts per window); keep `MAX_HANDSHAKES` and the per-IP limiter on that path. Keep the loopback/USB caveat in the docs.

### D5 low: queued actions outlive the session

`Press` jobs go to a worker over an unbounded `mpsc` channel. Up to 10 presses/s are accepted and each runs up to `ACTION_TIMEOUT` = 30 s serially; `Jobs.open` is only a counter, not a cap. When the session ends (disconnect, `unpair`, "settings changed") the worker's `for (req, job) in job_rx` still drains every buffered job before the thread scope joins, so a revoked or stolen phone can leave a backlog (for example 100 `night toggle` / `mode apply`) that runs after `unpair`. Needs a paired device.
Fix: cap `jobs.open` (4) and answer `Ack{ok:false,"busy"}`; give the worker an `AtomicBool` that the session sets on exit, checked before each job; also check `device_name(key)` before executing.

### D6 low: disk-space check does not subtract reservations

`decide` for `file.push` compares `free_space(dir) < size + FREE_MARGIN` but `hub.incoming` (bytes reserved by other open transfers, up to `INCOMING_MAX` 1 GiB) is not deducted. Two 500 MB offers on a 600 MB-free disk both pass (each asks the user, or none does for a trusted device); writes then fail with ENOSPC and the margin is gone. Fix: `free < size + FREE_MARGIN + hub.incoming`.

### D7 low: received file mode and pre-existing folder permissions

`Part::finish` sets 0644 and `ensure_dir` chmods 0700 only for folders it creates. A pre-existing `~/Downloads/stance` (typically 0755) exposes phone files to other local users. The docs call it a "quarantine folder"/"private directory". Fix: keep the file 0600 or tighten the dir when owned by us; or document.

### D8 low (uncertain): own binary path after an upgrade

`Deck::load()` stores `std::env::current_exe()`. On Linux that is the `/proc/self/exe` link target; if the binary is replaced by unlink+create (package manager, `install`) the value ends in ` (deleted)` and `run_tool` fails to spawn until the service restarts. Not reproduced; check `tests/upgrade.sh` coverage. Fix: strip the suffix and canonicalise, or resolve `stance` through `crate::tool`/PATH at run time with a fallback.

### D9 info: docs vs behaviour (`docs/deck.md:95-100`)

- "handshake time 5 s": per-read, not total (D1).
- "Replay ... Old recordings fail in a new session": a replayed IK message 1 is accepted by the server (D2), only the transport fails.
- "actions serialised per device" is true per session, not across multiple sessions of the same device.
- "Data streams into a temp file in a private directory" depends on D7.

### D10 info

- `add_device` replaces an existing device of the same name (new key): the QR holder can displace a phone entry (trust is revoked for `transfer.toml`, a notification is sent, so acceptable; see D3 for why the notification may not show).
- `Link::peer_msg` marks a transfer `Done`/`Declined` in the history before the stream state validates the message (`done before end` then ends the session). Cosmetic: a paired phone can show an unsent file as done.
- Test client `receive` writes with `std::fs::write` (follows a symlink in the target dir) and buffers up to 512 MiB in memory; test tool only.
- Clipboard from phone (`clip_from_phone = notify`) overwrites the PC clipboard without a prompt (documented). The notification preview collapses newlines (`plain`), so a multi-line payload looks like one line; consider showing "N lines" in the preview.
- Memory ceiling: 8 sessions x 2 open streams x 32 MiB clip images is about 512 MiB held in `In::Clip` buffers; only for paired phones with `clip_images` on.
- Private key `String`s are not zeroized (`Keypair` Debug is redacted; good).

## Checked, clean

- **Noise keys and patterns:** IK for sessions, XXpsk3 for pairing, mode byte mixed into prologue, schema in prologue; `pair_xx` verifies the PC static key against the QR before sending message 3; server verifies membership after message 1 and sends nothing on refusal. PSK is 256-bit from `/dev/urandom` (read_exact), compared only inside Noise. Transport counters belong to snow; any decrypt error ends the session; frames 1..=1024 pre-auth and 1..=16384 post-auth, `u16` length, zero length rejected.
- **Pairing window:** 120 s expiry checked at take and by the tick thread, QR SVG removed on take/expiry, `open_pairing` replaces an open window, device cap 16, names cleaned, `deck-devices.toml` strict (`deny_unknown_fields`), 0600 atomic writes, `read_checked` refuses group/world-writable and foreign-owned files, size-capped 64 KiB.
- **Key storage:** `deck-key.json` created 0600 via `atomic_write` (`O_NOFOLLOW`, `create_new`) in a private dir; no secret is logged (log lines carry peer IP, error message and device name only); `Keypair` Debug redacted; the QR payload (with PSK) exists only in the 0700 runtime dir and in the control reply to the same uid (SO_PEERCRED checked).
- **Rate limiting:** failures per IP/overall, prune on every call, map bounded by prune (IPs with no recent failure are dropped); global limit only blocks IPs that already failed. (Gaps: D1, D2.)
- **Stream state machine:** sid parity, strictly increasing peer sids (no reuse), `sid == 0` rejected, offers rate-limited and counted even when refused, size caps per kind, `size == 0` refused, hash must be 64 lowercase hex, `window <= min(size, WINDOW_MAX)`, `checked_add` on window credit, `received <= granted <= size` with all subtractions guarded (`granted - received`, `granted - sent`), end-before-all-data and done-before-end are protocol errors, cancel/decline/done crossing is covered by the 8-entry `recent` list, idle (30 s) and consent (60 s) timers, `close_all` reports every open stream. No overflow or underflow reachable.
- **Panics reachable from the network:** none. `proto.rs:parse_plain` indexes `b[1..4]` only after `len > DATA_HEADER`; `noise.rs` `out[..n]`/`buf[..n]` use `n` returned by snow; `pair.rs:dec` uses `get(i+1..i+3)?`; `link.rs` `data[*pos..end]` has `pos <= len`, `end = min(..)`; `transfer.rs` slices are on `rfind('.')` boundaries and the `is_char_boundary` loop, `&d[2..]` after `starts_with("~/")`; `client.rs` `data[pos..pos+n]` bounded by `data.len() - pos`. Mutex poisoning handled by `unwrap_or_else(into_inner)`. No `unwrap()`/`expect()` outside tests in the scanned files.
- **File receive path:** `clean_name` takes the last component after `/` and `\`, strips control/invisible characters, leading `.`/`-`/space, trailing `.`/space, empty -> `file`, 120-byte cap on a char boundary; temp file `.stance-part-<random>` created `O_EXCL|O_NOFOLLOW` 0600 in the target dir; final name by `link()` (never overwrites, ` (n)` suffix, 999 tries), fallback `renameat2(NOREPLACE)` then `O_EXCL` copy; size and SHA-256 checked before it is visible; temp removed on drop, crash leftovers swept at start; folder must be a real directory owned by us (symlinked folder refused); `download_dir` validated (no `..`, no control characters, absolute or `~/`); nothing is executed or opened; per-offer size cap (`max_file_mb` <= 512), `INCOMING_MAX` 1 GiB in flight, free space + 64 MiB margin (but see D6), one consent slot, cooldown after 3 refusals.
- **Clipboard apply:** `wl-copy --type <mime>` with a fixed text type or a type from `sniff_image` (content decides, BMP refused); data over stdin, never argv; 10 s timeout, child killed; text must be valid UTF-8; echo guard; notification text through `plain()` and `--` (`transfer::notify`).
- **Process spawning:** actions run our own binary by argv (no shell), `text_arg` rejects empty, over-long, control characters and a leading `-`; brightness `value` regex-checked (`+N`/`-N` is the only dash-leading argument and is parsed by the hand-written CLI); `deny_unknown_fields`, per-kind allowed-field check, closed action set; `run_tool` has timeout, output caps (4 MiB / 64 KiB) and kills the child. Button ids are matched exactly against the loaded list.
- **Control socket:** dir 0700, socket 0600, symlink refused, SO_PEERCRED uid check, 4 KiB request cap, 2 s read timeout; `send` accepts only absolute paths under 4096 bytes, `Source::open` opens once, checks regular file and size on the descriptor, re-checks size and mtime at the end.
- **Protocol 1 compatibility:** stream messages or data frames before `caps` end the session, the PC never sends stream traffic to such a client.
- **Test vectors module:** test-only, fixed keys marked `fixed_ephemeral_key_for_testing_only`, not compiled into release (`#[cfg(test)]`).
- **0.8.0 fixes still hold:** `Finished` precedes `Done` in `stream.rs:on_msg End`; `rename_noreplace` fallback present in `Part::finish`.
