## Findings

### S-01 medium: clip.json read-modify-write has no lock (lost update, a pause can vanish)
- src/clip.rs:405-422 (`put_config`), 427-437 (`pause`), `save_config` 439; src/feature.rs:128-141
- `put_config` and `pause` do `config()` -> modify -> `save_config()` with no flock (only the
  index has one). Two concurrent writers (panel retention click + pause, or `feature off clip`
  + pause) overwrite each other. A lost `pause` means capture keeps running while the user
  believes it is paused (privacy-relevant).
- Reproduced: 40 rounds of `stance clip pause 1h & stance clip config put --data '{"retention_days":7}'`
  in parallel: 10/40 ended with one of the two changes lost.
- Fix: take `store::lock_state_in(config dir or clip dir)` around config read-modify-write
  (and around `feature::set`'s features.json write); also re-check config under the lock in `add`.

### S-02 medium: store has no total size or item-count cap (disk fill, O(n) index rewrite per copy)
- src/clip.rs `add` / `prune_index` (retention is time only), MAX_IMAGE 32 MiB per item
- Retention default is 30 days and only time-based. Many distinct screenshots/images (or a
  script looping `wl-copy`) grow `blobs/` without bound (e.g. 50 x 5 MiB/day x 30 days = 7.5 GiB;
  a loop of 32 MiB images fills the disk in minutes). Every ingest also loads and rewrites the
  whole index.json under the lock, so cost grows with item count.
- Scenario: `while true; do head -c 3000000 /dev/urandom | wl-copy -t image/png` style loop
  (PNG magic prefix) with the shelf enabled.
- Fix: cap total blob bytes (e.g. 512 MiB-1 GiB) and item count (e.g. 5000), evicting oldest
  unpinned first; document it.

### S-03 medium: corrupt/unknown-format index silently wipes every blob
- src/clip.rs:`mutate` (index.json.corrupt branch) + `add` -> `sweep`
- When `load()` returns `invalid`, the index is renamed to `index.json.corrupt` and an empty index is
  used; the same call's `sweep(idx)` then deletes every blob (nothing references them), so
  the `.corrupt` file is useless and all history is gone. Realistic trigger: downgrade after a
  future version adds a new `Kind` variant or required field (serde fails for the whole file).
- Reproduced: 64 items/64 blobs, `echo '{bad' > index.json`, one ingest -> 1 blob left,
  index.json.corrupt kept but references nothing.
- Fix: skip `sweep` when recovering from a corrupt index (or move `blobs/` aside too), and
  parse the index tolerant of unknown kinds (`#[serde(other)]`) so a version skew is not "corrupt".

### S-04 low: link host spoof via backslash (`https://evil.com\@trusted.com/`)
- src/clip.rs:`link_host` (authority split on `/ ? #` only; `rsplit('@')`)
- Browsers (WHATWG) treat `\` like `/` for http(s), so the real host of
  `https://evil.com\@trusted.com/x` is evil.com, but stance stores kind=link, host="trusted.com"
  and the panel shows it as the link's host (StanceClip.qml:724).
- Reproduced: ingest of that string -> `"host":"trusted.com"`.
- Fix: return None (plain text) if the URL contains `\`, `%`-encoded host chars or `@` in the authority
  at all.

### S-05 low: QML shows phone-supplied / doctor text with default AutoText (rich text injection)
- quickshell/stance/StanceSettings.qml:886 (`Body { text: drow.modelData.name }`, device name from the
  phone), :1032 (`Dim { text: modelData.message }`, doctor output), :572/:909/:982 (error strings),
  StanceChip label (StanceChip.qml:43) for monitor/mode names
- `Body`/`Dim`/`Note` are `Text` components without `textFormat: Text.PlainText`. Device names are only
  length-bounded and control-stripped (src/deck/proto.rs:115), so `<` and `>` pass. Qt AutoText
  renders `<b>`, `<a>`, `<img src=...>` (can fetch an image URL). Needs a paired device
  (user-approved) so impact is spoofing/tracking only. Violates checklist "user data as PlainText".
- Fix: set `textFormat: Text.PlainText` in `component Body/Dim/Note/Err` and in StanceChip.

### S-06 low: configuration JSON accepts unknown keys
- src/clip.rs:`Config` (`#[serde(default)]`, no `deny_unknown_fields`); src/feature.rs:`load_at` drops unknown keys
  silently
- Reproduced: clip.json `{"enabled":true,"bogus":1}` loads fine. A hand edited `paused_until` or a
  typo such as `"retenton_days"` is silently ignored (retention stays 30 days: privacy surprise).
- Fix: `deny_unknown_fields` on `Config` (keep `paused_until`); error out in `load_at` for unknown
  feature names.

### S-07 low: `feature::set` is not atomic across its steps
- src/feature.rs:`set`
- features.json is written first, then `put_config` (may fail on a bad clip.json) and only then
  the units are touched. A failure leaves features.json saying off/on while the store config
  and units say otherwise; the lost-update problem of S-01 applies to features.json too.
- Fix: lock, do the fallible steps first or roll back, report partial state in `notes`.

### S-08 low: index fields are trusted when building blob paths
- src/clip.rs:`blob_path` / `open_blob` (`format!("{}.{}", e.sha256, e.ext)`)
- `sha256`/`ext` come from index.json with no validation (64 hex / [a-z0-9]{1,4}). A tampered index
  (same user, or a restored/shared backup) with `ext":"txt/../../../x"` makes `clip get`/`copy`/search
  open files outside `blobs/` (O_NOFOLLOW only covers the last component).
  Reproduced: `clip get 1` tried `blobs/<sha>.txt/../../../../cfg/clip.json` (failed with ENOTDIR here only
  because of the layout).
- Fix: validate on load (`sha256` 64 lowercase hex, `ext` in the sniff allowlist, `kind` consistent) and
  drop bad entries.

### S-09 low: some readers are not size-capped / TOCTOU on import
- src/clip.rs:`load` (`read_to_string` of index.json, uncapped); src/theme.rs:`read_import` (metadata size check, then
  unbounded `fs::read`; file can grow in between; `Themes::user` does not bound the number of
  theme files, each up to 64 KiB, all parsed on every `theme list`)
- Fix: `File::take(MAX+1)` on the opened handle (also `fstat` that same handle); cap index size (e.g. 64 MiB) and
  user theme count (e.g. 200).

### S-10 low: `doctor --report` is not free of personal data
- src/main.rs:`bug_report`, src/doctor.rs:201-237, 287, 294, 343+ (shell_checks)
- Only ids instance/socket1/socket2 are filtered. The remaining checks print full paths:
  `main config /home/<user>/.config/hypr/hyprland.lua`, persist path, `/run/user/<uid>`, the
  user's Quickshell config dir names, clip config error paths. The comment promises "Nothing personal
  beyond what doctor prints", which is accurate but the username/uid/config names land in public
  issues. Static finding (doctor stops early without Hyprland, so it could not be run end to end here).
- Fix: in report mode replace `$HOME` with `~`, drop `runtime_dir`/`stance_runtime` paths and
  non-stance shell config names; show a "review before posting" line.

### S-11 low: theme names and fonts accept Unicode format/bidi characters
- src/theme.rs:`validate` / `font_name` (only `char::is_control`)
- Reproduced: import of a theme with `"name":"‮evil"` succeeds. Rendered in the theme tile
  (PlainText, so only visual reordering), clip.rs already strips these for previews (`is_invisible`).
- Fix: reuse `is_invisible` (reject) for name/fontFamily/iconFont.

### S-12 low: PNG dimensions are stored unvalidated
- src/clip.rs:`png_size`, `classify`
- Reproduced: a 59-byte PNG with IHDR 4294967295x4294967295 is stored and listed with
  `w/h = 4294967295`; the panel shows it in the card (StanceClip.qml:677) and Qt must decode it
  (sourceSize 320x200/1600 only limits scaling, not decode memory; Qt's allocation limit is the only guard).
  Also all image formats are decoded in the panel process (libpng/libwebp/... attack surface from any
  copied image).
- Fix: reject w or h == 0 or > 32768 (or w*h above ~100 MP) at ingest; document the decoder surface.

### S-13 low: `clip get` and `setup` print stored/process text to the terminal raw
- src/main.rs:`clip_cmd` "get" (`print!("{s}")`), src/setup.rs:`detect` (`qs -c` argument echoed in the "detected" note)
- Reproduced: ingesting `ESC]0;pwn BEL ...` then `stance clip get 3` outputs the ESC/BEL bytes
  (terminal title/escape injection when a user runs `clip get` on a hostile copy).
- Fix: for non-`--json` output of `get`, replace C0/C1 control chars except `\n\t`; sanitize the detect string.

### S-14 low: external calls without timeout
- src/feature.rs:84,94 (`systemctl cat/is-active` via `.status()`), src/setup.rs:166,
  src/clip.rs:711 (`wl-copy` via `.status()`)
- Checklist: "absolute path, argv list, timeout". These are absolute argv (good) but a hung systemd or
  compositor blocks `feature list` (called by the panel at startup), `setup` and `clip copy` forever.
  `tool::run_tool` already provides kill+reap.
- Fix: route all three through `tool::run_tool` (wl-copy: read stdin from the blob file via a
  `Stdio` option or add a variant that takes stdin).

### S-15 info: QML / packaging hardening notes
- StanceService.qml:255 `["mkdir","-p",...]` is a relative command (PATH lookup); use FileView / absolute `/usr/bin/mkdir`.
- `svc.bin` defaults to `stance` via PATH and `STANCE_BIN` env redirects what the panel executes (documented as test hook); consider
  ignoring `STANCE_BIN` unless it is absolute.
- Image URL is `"file://" + path` without percent-encoding (StanceClip.qml:615,666): a `$XDG_DATA_HOME` containing `#`, `%` or `?`
  breaks previews (functional bug, not security).
- panel.json is written by `FileView.setText` (non-atomic, default umask, not 0600).
- contrib/stance-panel.service has no hardening (`NoNewPrivileges=yes` fits) and the installed unit hard-codes
  `/usr/share/stance/quickshell` while `stance setup` prints the checkout path in the step text.

### S-16 info: SIGPIPE default action is also restored for mutating commands
- src/main.rs:206-219
- Only `deck|daemon|guardian` keep SIG_IGN. `set`, `layout`, `mode apply` etc. get SIG_DFL, so a
  reader that closes stdout early (`stance set ... | head -1`) can terminate the process silently at its
  first stdout write. Verified that socket writes are not affected (Rust uses MSG_NOSIGNAL; pipe writes are).
  The guardian is spawned separately so rollback is not lost, but prefer limiting SIG_DFL to read-only commands.

### S-17 info: docs and metadata drift
- Cargo.toml `version = "0.2.0"` (so `doctor --report` prints `stance 0.2.0`); bump with the release.
- docs/clip.md says the lock file is `index.lock`; the code uses `<clip dir>/lock`.
- docs/clip.md should state that a damaged index loses blobs (S-03) and that `rm` keeps content on disk for 24 h.
- `clip config` (non-json) can print a huge number or panic in debug if the pause deadline passes between
  `paused(now())` and `t - now()` (src/main.rs, "config" show; use `saturating_sub`).

### S-18 info: removed items stay readable on disk for 24 h
- src/clip.rs:`prune_index` (TRASH_SECS)
- `clip rm` of a copied password only sets `trashed`; preview and blob remain (0600, unencrypted) until the
  next prune after 24 h. Documented as soft delete, but there is no "delete now" path other than
  `clear --all`. Suggest `rm --purge` or an explicit panel hint.

## Checked, no issue (per checklist item)
- Process spawning: all new spawns use absolute paths via `tool::find` (/usr/bin first) and argv lists; no shell
  strings. QML Processes pass `[bin, "clip", ...]` arrays; ids are `^[0-9]+$`-validated in `sanitize` and
  `parse_id`; `--query`/`--out` take user text as a value (tested: `--query --json`, `--query --`, `--query --all` are
  swallowed as the value, no flag injection). ETXTBSY retry in `tool.rs` is correct (one retry, no loop). Timeouts exist in
  `run_tool` (but see S-14).
- Paths: ids validated before any join (`parse_id`, theme `valid_id`, `../x` and `../../etc/passwd` refused);
  blobs dir symlink refused (reproduced: ingest through a symlinked `blobs` fails, victim dir untouched);
  blob symlink refused (ELOOP); `atomic_write` refuses symlinks; theme export refuses symlink/non-regular
  target, import refuses FIFO/non-regular.
- State files: index is written under flock with atomic rename and 0600/0700 (verified modes); 60 parallel ingests gave
  60 unique ids, no lost entries, no stray tmp files; blob written before index so a crash leaves only
  orphans (see S-01/S-03 for the exceptions). `put_config` rejects `paused_until` and unknown keys in patches.
- Input limits: text 256 KiB and image 32 MiB read with max+1 and dropped (tested 300 KB text: not stored);
  theme/config readers capped at 64 KiB (exceptions in S-09); theme JSON uses `deny_unknown_fields`, colours/metrics range-checked
  (out-of-range and 1e999 rejected, control chars in fonts rejected).
- Deck: not changed since v0.2.0 except unit file (`stance-deck.service` unchanged semantics); not re-audited in this scan.
- Clipboard: `CLIPBOARD_STATE` other than `data` stored nothing (tested sensitive and unset), pause honoured (tested), disabled
  by default, nothing is logged beyond error strings (no clip text in any eprintln), file-manager copies and NUL/invalid UTF-8 refused,
  previews strip bidi/zero-width/control chars.
- QML: clip previews, hosts, theme names use PlainText (StanceClip.qml 275/397/581/633/693/723/733, StanceAppearance 233/388);
  no `eval`, `Qt.createQmlObject`, no string-built commands; image paths are confined to the clip dir by `safePath`
  (exceptions: S-05 for Body/Dim/Chip).
- Secrets: clip contents never appear in `--json` errors; `doctor --report` limits in S-10.
- Error paths: no `unwrap`/`expect` reachable from input in the new clip/theme/feature/setup paths (the `expect` in builtins is
  compile-time data covered by a test); `parse_duration` slicing is on an ASCII byte boundary.
- Docs vs behaviour: see S-17.

## New findings from the fixes
- N-01 low: while `index.json.corrupt` exists `sweep` is disabled entirely, so `purge`, `prune`, retention, the S-02 caps and `rm` stop freeing blobs
  (reproduced: `rm` then `purge` printed "deleted 1 ... for good" but the blob count stayed 24 -> 24, i.e. removed content stays on disk, and the
  store can grow unbounded). Only `clear --all` ends it (and wipes everything). Fix: on recovery, rebuild the index from blobs or move
  `blobs/` + the corrupt file aside together (restorable); or sweep only blobs not older than the corrupt file's mtime; at least tell the user
  (doctor warning) when `index.json.corrupt` exists.
- N-02 info: `bug_report` redacts `$USER` by plain substring replace before `/run/user/<uid>`; a short or common user name (e.g. `run`, `usr`) would
  mangle unrelated text. Replace path components only, or do the uid replace first.
- N-03 info: see S-10, the user's own Quickshell config names remain in the report.
- N-04 low (functional): use per-segment `encodeURIComponent` instead of `encodeURI` for file URLs (StanceClip.qml:615,666, StanceService.qml folder).

No new security-relevant regressions found: lock files are 0600 under O_NOFOLLOW, `config.lock` lives in the already-validated private clip dir
(no deadlock: locks are released before `prune`, `feature::set` takes `features.lock` and releases it before `put_config`), `status_timeout`
kills and reaps, and `load` drops tampered entries before any path is built.
