## Findings
### M-01 low (data loss, newer-schema guard bypass): `migrate::guard_json/guard_toml` fail open
- src/migrate.rs: `toml_schema` (`u32::try_from` fails -> 1; negative -> 1), `guard_json` (`json_schema` error -> `unwrap_or(1)`),
  `read_small` (file > 1 MiB -> None -> "passes").
- Repro (verified): `printf 'schema = 3\n# <2 MiB comment>' > rules.toml; stance rules put --data '{"rule":[]}'` overwrites it
  (same with `schema = 5000000000` or `-4`). A genuinely newer file is replaced by schema 1.
- Fix: guard returns `newer_schema` (or refuses) when the file exists but is oversized/unparsable-schema/out-of-range; only a
  missing file passes. Unparsable-as-whole files may still be overwritten deliberately, but say so.
### M-02 info: `stance events` hello is optimistic without a compositor
- `Hyprland::connect()` is lazy, so `hello` says `backend":"hyprland","monitor_events":true`, then `backend_error` (code runtime_dir)
  follows; `stance caps` also reports hyprland caps with no session. UIs should treat `backend_error` as authoritative; consider
  a cheap socket-exists check or document it in docs/protocol.md.
### M-03 info: events watches are never re-armed if the config dir itself is removed/replaced
- src/events.rs: IN_IGNORED drops the watch; only `themes/`/`modes/` re-add via the config watch. Deleting `~/.config/stance` while
  `events` runs silences file events until restart. Edge case.
### M-04 info: `doctor --report` with STANCE_BACKEND=fake resolves fake state to relative `fake.json` (cwd)
- src/main.rs `backend::connect(None, &PathBuf::new())`. Read-only (no write), test-only backend; pass a real state dir.
### M-05 info: STANCE_FAKE_STATE is an arbitrary absolute path (read, and written by fake `set`)
- Not a boundary (same user controls env and binary). Verified: non-JSON file is refused and left intact (symlink too);
  `deny_unknown_fields` on `Saved`. Only note: a valid fake.json at that path would be rewritten.
